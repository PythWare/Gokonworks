Akiba's Trip: Undead & Undressed Therion Script Function Reference

This guide was written by PythWare on 8/6/2026, so as of that date this is all the public info on Therion and usage. This guide may be updated later on.

How to run Therion:

therion.exe is the script compiler Acquire shipped inside volume.dat.
 Example directory where Therion is:  Unpacked_Files\lang_us\script\therion.exe

It turns a .sol source file into a .sx file. .sol is the script you write while .sx is the compiled version the game uses. Copy therion.exe somewhere convenient and run

Example commands:

   Compile 1 Script
     therion.exe -c MyScene.sol -o MyScene.sx

   Compile with #include files
     therion.exe -c MyScene.sol -o MyScene.sx -P C:\akiba\myincludes\

   Full paths if the files are elsewhere
     therion.exe -c C:\work\scene.sol -o C:\work\scene.sx -P C:\work\inc\

   A quicky test
     therion.exe
     print("hello");        <- type a statement, press Enter
     print(1+1);            <- prints 2
                            <- blank line quits

Options:

   -c <file>   the source file to compile          (required)
   -o <file>   where to write the compiled result  (required)
   -P <path>   folder holding your #include files  (optional)
   -p          does nothing. It's parsed and then never used, ignore it.

Exit Codes:
   0  success       1  bad arguments or input file missing
   2  compile error 3  could not write the output file

Read this before writing anything:

Save your .sol and .h files as UTF-16 LE with a BOM.
In Notepad: Save As -> Encoding: Unicode. In VS Code: UTF-16 LE.
A UTF-8 file will fail with a useless error.

Error mesages are nearly useless. A syntax error prints error[] line:1 with an empty message and the line number is often wrong. Compile often and change one thing at a time.

The language looks like JavaScript. Functions are values:
       Scene_010 = def
       {
           Common_SceneChangeStartOut();
           StartMainMission();
           Wait(30);
       };
It has var, if, while, for, switch, return, objects, new, lists, #define, #include, and background threads via StartThread.

Putting a script in the game: 

compile to .sx, place it in a folder mirroring the game layout (like lang_us\script\event\), then bottle it with the Gokonworks Mod Creator and pour it from the shelf.

How functions are called, partly solved:

The functions above aren't all global. Many are methods on engine objects, so the real call looks like this:

       Character.PauseTask();
       Mission.StartMainMission();
       TalkEvent.PlayTalkEvent(TALKEVENT_MM_000_000);

These engine objects appear in the shipped scripts, with the number of scripts each shows up in:

       Character      153 scripts
       Mission        153 scripts
       Param          152 scripts
       Sound          152 scripts
       Camera         152 scripts
       Effect         152 scripts
       TalkEvent      152 scripts
       UI             152 scripts
       Locator        152 scripts
       Map            63 scripts
       Battle         62 scripts
       Object         24 scripts

 Which function belongs to which object isn't yet solved. We can read the names out of the bytecode but not yet the ownership. To find out how a specific function is called, look at a script that uses it.

       Require("event/common");

What's still unknown:

Which engine object owns which function, see section 4.
 
What arguments each function takes and in what order. Copy the call from a shipped script that already does what you want.

The full opcode set, so there is no decompiler yet. Names and text can be read back out of a .sx but comments and formatting are gone for good and control flow has to be reconstructed by hand.

Constant names such as TALKEVENT_MM_000_000 are readable but the full list of valid values isn't known.
